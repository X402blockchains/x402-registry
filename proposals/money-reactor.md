# Money Reactor
- Type: API
- Description: Agent-native micro APIs priced for autonomous agents: a funded crypto/GitHub bounty feed with trust filtering (GET `/api/bounties`, $0.01), GitHub repository honeypot trust scoring with GO/CAUTION/HONEYPOT_RISK verdicts (GET `/api/honeypot?repo=owner/name`, $0.002), and a one-line pre-flight verdict (GET `/api/verdict?repo=owner/name`, $0.001). Responses are plain JSON; every 402 response carries full payment requirements for both x402 v1 and v2 plus Bazaar discovery metadata (method, output schema with examples).

- Public repository: https://github.com/makar52nn2016-jpg/money-reactor
- Networks and chain identifiers: Base mainnet (eip155:8453)
- Paid resource URLs and HTTP methods: GET `<origin>/api/bounties` ($0.01); GET `<origin>/api/honeypot?repo=owner/name` ($0.002); GET `<origin>/api/verdict?repo=owner/name` ($0.001). Prices are also published in the repo README and in the live discovery catalog.
- Live origin resolver (single canonical source): https://raw.githubusercontent.com/makar52nn2016-jpg/money-reactor/main/live-url.json → field `.url` (`lane: edge-canonical`). The public URL is a Cloudflare tunnel fronting a worker in auto-chained 6h shifts with a 10-min watchdog that restarts a dead lane and republishes the URL within ~10 minutes; the tunnel hostname rotates on shift change, so agents MUST resolve `.url` at runtime instead of caching a host. Legacy mirror: `reactor/state/service_url.json`; static discovery mirror with the same URL: https://makar52nn2016-jpg.github.io/money-reactor/.well-known/x402-info.json
- x402 version and payment scheme: x402 v2 (`exact`, network `eip155:8453`) and x402 v1 (`exact`, network `base`) — both advertised in every 402 response. Wire format: v1 clients send `X-PAYMENT`, v2 clients send `PAYMENT-SIGNATURE` (both accepted); the settlement receipt is returned in both `X-PAYMENT-RESPONSE` and `PAYMENT-RESPONSE` headers. `PAYMENT-REQUIRED` (base64) carries the 402 challenge for both versions.
- Token contract or mint, decimals: USDC (Base) `0x833589fCD6eDb6E08f4c7C32D4f71b54bdA02913`, 6 decimals.
- Seller payment recipient addresses: `0xf47b7e5912Fd4218aC4c992Cdc6FAE04e1fF512E` (this is the sole payTo address in all payment requirements).
- Facilitator URL and supported endpoint: `https://x402.org/facilitator` (the public Coinbase CDP production x402 facilitator; no authentication required for `/verify` and `/settle` of standard EIP-3009 payments), with `https://api.cdp.coinbase.com/platform/v2/x402` as failover. The service POSTs the payment header + requirements to `/verify` (read-only, may be tried against each facilitator) and then to `/settle` on the facilitator that verified. Verification is server-side; the buyer's signature is an EIP-3009 `transferWithAuthorization` (v2) / EIP-712 permit-style header (v1).
- Facilitator signer / relayer addresses (if applicable): no custom relayer is operated; the facilitator itself submits the on-chain transfer and returns the transaction hash. There is no self-hosted settlement.
- Settlement semantics (implemented in `service/main.mjs`): paid data unlocks ONLY when the settle receipt has `success === true` AND a `0x…` transaction hash; malformed receipts or missing fields return `503 settlement_unverified` and never unlock content. `402 invalid_payment` / `402 settle_failed` are confirmed rejections (no funds moved, a new payment is required). `503 settlement_unknown` covers facilitator 5xx / network timeouts — the outcome is unknown, paid data is withheld, and the caller is told NOT to re-pay with the same authorization and to contact the operator for reconciliation (replay-safe: `/settle` is never retried against a second facilitator after an unknown outcome).
- Example successful settlement hashes and explorer links: none yet — the service is live and Bazaar-validated but has not recorded its first sale, and the operator will not invent hashes. A clearly-labelled operator test payment (resources/method/price/UTC time/decoded receipt/redacted HTTP response) will be appended to this proposal via a new commit as soon as the first mainnet settlement is recorded; see the PR discussion for the live status.
- Ownership evidence (domain-hosted proof or public project reference): the payTo address is published in the repository README (with the settlement-flow documentation), in the Pages-site storefront, in `server.json` at the repo root, and returned verbatim by every 402/health response from the live origin (resolve the current origin via the live-url.json link above).
